# 引擎与平衡

## 一句话

两条并排通道、同一颗起手球；每破一块玻璃，红方球数 ×2、蓝方球数 +15。
球数决定单位时间的撞击次数，先打穿整堆玻璃的一方赢。

## 每一步（1/120 秒）

`Lane.step()`：

1. `spawn()` —— 场上球数不足 `min(balls, maxBalls)` 时，从顶板下面补发，每步最多 4 颗
2. `integrate()` —— 每颗球：重力 → 位移 → 侧壁 / 顶板反射 → 玻璃顶面
   - 玻璃顶面是**弹力地板**：反弹速度 `sqrt(2·g·h)`，`h` 取空窗高度的 82%–98%，球回到顶板附近
   - 落地时竖直速度 ≥ `minHitSpeed`（80）才算一次撞击，扣 1 点血
   - 反弹时加 ±0.18 弧度扰动（多项式 sin/cos），横向速度 ×0.9 防止越弹越平
3. `collide()` —— 球-球碰撞
   - 宽相：格子边长 = 球直径，计数排序建格，查 3×3 邻格
   - 窄相：重叠就沿法向各推一半；相向运动时交换法向动量（等质量、弹性系数 1）
   - 夹回通道和玻璃顶面之上
4. 采样 / 录像

撞击扣到 0 血 → 破镜：按规则改球数、下一层成为新的地板；全部碎完记 `finishTime`，
同时冻结结算快照。之后赛道仍可继续推进（只给画面用），结算不再变。

## 确定性

- 随机数：`mulberry32(seed + teamSalt)`，红 `0x9e37`、蓝 `0x5f21`
- 热路径只用 + − × ÷、`Math.sqrt`、`Math.floor/abs/min/max`，结果由 IEEE 754 唯一确定
- 不用 `Math.sin/cos/pow`：各 JS 引擎实现可以差最后一位，混沌系统会把这一位放大成胜负差异
- 测试 `引擎热路径不用 Math.sin / Math.cos` 会扫描 `engine.ts` 源码守住这一条
- 浏览器 Worker 重算的结果与服务端结算逐位比对，画面下方显示比对结果

## 录像

`simulateWithTracks(cfg, 1/30)`：每 1/30 秒记一帧**全部**球坐标（×32 量化进 `Uint16Array`），
打穿那一刻额外记一帧。跑到双方都打穿后再多跑 1.5 秒，先打穿的一侧球继续弹，不会定格。
只在浏览器 Worker 里录，不走网络。

## 判胜

```
都打穿 → 用时短的赢（同一帧判平）
只有一方打穿 → 那一方赢
都没打穿 → 破镜多的赢
```

## 平衡

标准局：13 层，血量 `6 × 1.56ⁱ`（`DEFAULT_CURVE`），通道容量 512，重力 2600。
目标是视频效果：红方前 12 块落后，最后一块反超，险胜。

| 检查 | 结果 |
|---|---|
| 64 个随机种子 | 红方 64/64，领先 0.29–1.47s，中位 0.91s |
| 同曲线 10 层 | 蓝方领先约 10.6s |
| 同曲线 16 层 | 红方领先约 30s |

相变很陡：倍率 1.55 → 1.54 能把标准局从红方 16/16 翻成 0/16。
改任何物理常量或默认参数都要重跑 `npm run balance`，必要时 `npm run sweep`。
