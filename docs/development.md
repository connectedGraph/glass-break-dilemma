# 玻璃对撞实验室 · Glass Break Dilemma

把短视频里那个「×2 还是 +15，谁先砸穿整堆玻璃」的玩法做成了一个可玩的网页：
两条并排通道、同一道题、同一颗球，两种成长规则对撞，押完看回放。

TypeScript 全栈：客户端 Preact + Canvas + Web Worker，服务端 Hono + SQLite，
物理引擎是一份两边共用的纯 TS 模块——每颗球独立积分、球与球真实碰撞，浏览器里看到的画面
就是这份引擎算出来的，并且和服务端判胜用的结果逐位比对。

---

## 玩法

一条竖直通道，顶部挡板、底部堆着若干块玻璃板，从上到下越来越厚：

```
   6      ← 最上面，最先被打到
   9
  15
  23
  ...
1246      ← 最下面，最厚（6 × 1.56ⁱ）
```

球从顶板下面落下，在顶板和「当前最上面那块存活玻璃」之间上下弹，
球与球之间互相碰撞；每落到玻璃上一次扣 1 点血，血空就碎，空窗往下延伸一层。

双方唯一的区别是**每破一块之后，场上球数怎么变**：

| | 规则 | 序列 |
|---|---|---|
| RED | ×2 | 1 → 2 → 4 → 8 → 16 → 32 → … |
| BLUE | +15 | 1 → 16 → 31 → 46 → 61 → … |

球多 = 单位时间砸得多。所以蓝方第一块碎掉就铺满通道、一路碾压；
红方前期只有一颗球慢得要命，得撑到复利滚起来才能反超。

**谁先砸穿整堆谁赢；层数相同时用时短的赢。**

### 标准局为什么是红方险胜

两条曲线在「破 7 块」附近交叉（2⁷ = 128 > 1 + 15×7 = 106）。标准局的血量曲线
（6 × 1.56ⁱ，13 层）是扫参扫出来的：红方前 12 块一直落后，第 12 块还慢 4 秒左右，
最后一块 1246 血上靠 512 颗球反超——就是视频里那种效果。

这不是写死的结局，是同一套物理在这组参数下的结果。同一条曲线少 3 层蓝方赢、多 3 层红方碾压：

| 预设 | 层数 | 时长 | 结果（16 个种子） |
|---|---|---|---|
| 标准局 | 13 | ~31s | 红方 16/16，领先 0.70–1.42s |
| 马拉松 | 16 | ~79s | 红方 16/16，领先约 30s |
| 闪击 | 10 | ~26s | 蓝方 16/16，领先约 10.6s |

标准局在 64 个随机种子下红方全胜，领先 0.29–1.47s（`server/src/cli/robust.ts`）。
相变很陡：倍率改成 1.54，标准局就变成蓝方 16/16。

## 三屏

- **今日题**：当天一份 seed，押红或押蓝 → 立刻看完整回放 + 逐层对照。
  押注前题面接口不下发 seed，所以前端算不出答案。
- **实验室**：层数 / 首层血量 / 血量倍率 / 重力 / 通道容量 / 球-球碰撞开关 / 双方规则 / seed
  全可调，浏览器 Worker 里重算，附一条数学上的球数交叉曲线。
- **原理**：复利对线性的推导、为什么实际对局比纯数学更复杂、这个项目在算什么。

## 架构

```
shared/src/          ← 客户端和服务端共用的唯一内核
  physics.ts            常量、几何、类型
  engine.ts             Lane（逐球积分 + 网格宽相球-球碰撞）、simulate、judge、录像

server/src/          ← Hono + node:sqlite
  app.ts                路由装配（测试里直接 app.request()）
  daily.ts              日期 + 预设 → seed（sha256），题面脱敏
  db.ts                 投票与对局记录
  compress.ts           极简 gzip 中间件
  routes/               presets / daily / simulate / stats / votes
  cli/                  probe、balance、sweep（调参与回归）
  test/                 engine + api

client/src/          ← Preact，无路由库
  game/sim.worker.ts      Web Worker：跑 shared 引擎，录每帧全部球坐标
  game/Playback.ts        回放：按时间取相邻两帧插值
  render/LaneRenderer.ts  双屏 Canvas：玻璃、球群（精灵贴图）、碎屑、数字 pop、打穿标记
  ui/Arena.tsx            竞技场：规则栏 + 双屏 + 时间轴
  pages/                  PlayScreen / LabScreen / AboutScreen
```

### 关键设计

**1. 浏览器自己算，服务端只做裁判。**
揭晓接口只下发配置（含 seed）和结算。浏览器在 Web Worker 里用同一份引擎重跑整局，
录每 1/30 秒全部球的坐标（不抽样，每帧几百颗）再回放，然后把胜负、打穿时间、
撞击次数和服务端结算逐位比对，结果显示在画面下方。押注的对错只认服务端算的。

**2. 跨引擎逐位一致。**
物理热路径只用 + − × ÷ 和 `Math.sqrt`（IEEE 754 规定结果唯一）；角度扰动用多项式，
不用 `Math.sin`/`Math.cos`；血量曲线用连乘，不用 `Math.pow`。多球碰撞是混沌系统，
差最后一位就会差一个胜负，所以这条有测试守着。

**3. 球群一直上下弹。**
玻璃顶面是弹力地板，把球送回顶板附近；球-球碰撞完全弹性。
早期用 0.9 的碰撞弹性时，几百颗球很快耗光动能堆在玻璃上，看起来像卡住了。

## 跑起来

```bash
./install.sh        # 装依赖（幂等）
./run.sh            # 后端 :8091 + 前端构建产物同源
./run.sh dev        # 后端 :8091 + Vite :5181（热更新）
./run.sh stop|status|log
```

首次构建后访问 http://127.0.0.1:8091 。

### 其他命令

```bash
npm test                    # engine + api 共 33 项
npm run typecheck           # 三包 tsc
npm run sim                 # 命令行跑一局看数值
npm run balance             # 三档预设的胜率与领先秒数
bash server/src/cli/sweep.sh        # 12 片并行扫参
```

## API

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/health` | 探活 |

| GET | `/api/daily?preset=` | 当天题面（**不含 seed**） |
| GET | `/api/daily/reveal?day=&preset=` | 配置（含 seed）+ 结算，浏览器据此重算 |

| GET | `/api/stats?day=&preset=` | 当日押注比例 |
| POST | `/api/simulate` | 任意参数对局（实验室用） |
| GET | `/api/curve?n=` | ×2 / +15 的纯数学序列 |

## 已知边界

- 通道容量 512 颗，两边相同。红方 2¹³ 理论上会到 8192 颗，通道物理上装不下；
  截断点已经算进平衡里。
- 标准局的结果对种子不敏感（64 个种子都是红方险胜），所以「每日竞猜」在标准局上没有悬念，
  悬念在闪击 / 马拉松和实验室里。
- 排行榜只有当日押注比例，没有跨日积分。
